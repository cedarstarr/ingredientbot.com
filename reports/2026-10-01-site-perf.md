## HIGH

1. **[ROOT_LAYOUT_FORCES_DYNAMIC]** `src/app/layout.tsx:44`
   Root layout awaits headers() (x-vercel-ip-country, x-nonce) and cookies() (cookie-consent), which opts every route into dynamic rendering. export const revalidate = 3600 on /ingredients, /ingredients/[slug], /allergens, /allergens/[slug], /r/[slug] and generateStaticParams on /recipes/[cuisine] are therefore inert; public SEO pages (/, /recipes, /recipes/[cuisine], /ingredients*, /allergens*, /r/*, /terms, /privacy) hit the DB and render per request. Note the CSP nonce from middleware is also coupled to dynamic rendering, so the fix is a tradeoff.
   Fix: Move EU-country and consent reading into a small client component (or a dynamic Suspense-wrapped leaf) so the layout stays static. Decide whether CSP nonce is needed on public pages (middleware could skip nonce for public routes, or enforce hash-based CSP). Then ISR/static generation on public pages takes effect.

2. **[MISSING_STATIC_PARAMS]** `src/app/r/[slug]/page.tsx:17`
   Public content routes /r/[slug] (~1000 recipes), /ingredients/[slug] and /allergens/[slug] (max 15) are bounded datasets with revalidate=3600 but no generateStaticParams, so they are never prerendered. Only takes effect once the root-layout dynamic opt-in is removed.
   Fix: Export generateStaticParams (select publicSlug/slug with the same published gates as sitemap.ts, take a cap such as 1000 for recipes) and keep dynamicParams true.

## MEDIUM

3. **[SITEMAP_SEQUENTIAL_FORCE_DYNAMIC]** `src/app/sitemap.ts:17`
   Four independent awaits (recipe findMany take 10000, ingredient findMany take 10000, recipe groupBy, allergen findMany) run sequentially on every crawler request, and the route is force-dynamic with no caching.
   Fix: Wrap in Promise.all and replace force-dynamic with export const revalidate = 3600 or cache via unstable_cache.

4. **[MISSING_CUISINE_INDEX]** `prisma/schema.prisma:262`
   Public recipe queries filter and group by cuisine (groupBy cuisine in /recipes, /recipes/[cuisine] resolveCuisine and generateStaticParams, and sitemap; findMany where isPublic + cuisine in /r/[slug] related and /recipes/[cuisine]), but the only supporting index is (isPublic, nonStapleIngredientCount). resolveCuisine runs a full groupBy on every cuisine page render.
   Fix: Add @@index([isPublic, cuisine]) to Recipe (migration required).

5. **[UNBOUNDED_SELECT_PUBLIC_RECIPE]** `src/app/r/[slug]/page.tsx:22`
   getPublicRecipe uses findUnique with no select, loading every Recipe column including rawText (full AI response text), modifications and nutrition JSON on a public, high-traffic share page; the page only needs title/description/times/cuisine/tags/allergen fields/recipeData.
   Fix: Add select listing only the fields rendered and used in metadata/JSON-LD, omitting rawText, modifications, sourceIngredients.

## Auditor notes

Image phase is clean (no <img> or next/image usage at all), fonts use next/font, scripts are nonce-handled, no CSS-in-JS, Prisma uses pg adapter with max:5 pool; authenticated pages already parallelize queries and cap findMany. Could not verify runtime rendering mode (static vs dynamic) without a build; the dynamic opt-in is inferred from headers()/cookies() in the root layout.
