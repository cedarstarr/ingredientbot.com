## Failures fixed

**1. `history-search.spec.ts` — "history heading shows total recipe count"** (regressed with FOU-321)

The test did a one-shot `await page.getByRole('main').textContent()` and then
`expect(string).toMatch(/\d+ recipe/)`. `beforeEach` only waits for `domcontentloaded`, so
it read the page mid-load and matched `"Loading…"` followed by the new `AllergenDisclaimer`
text. The race was always there; FOU-321's disclaimer changed the loading-state text enough
to expose it.

The app is correct — `history-client.tsx:101` renders `{total} recipe{s} generated`.

Fixed by asserting on the locator instead of an extracted string:
`await expect(page.getByRole('main')).toContainText(/\d+ recipe/)`. Same regex, same
strictness, but Playwright retries until the count renders. Every other test in the file
already used the retrying form; this one was the outlier.

**2. `collections.spec.ts` — SSR stream doubling**

`getByTestId('collections-heading')` resolved to 2 elements and tripped strict mode. Grep
finds exactly one emitter (`collections-client.tsx:104`), so this is the documented Next
early-closed-stream orphan, not a duplicate component. Scoped both usages through
`getByRole('main')` per the selector standard. `.first()` was not used — it can select the
hidden orphan.
