# FOU-344 — per-account login lockout — ingredientbot.com — 2026-09-09

**E2E gate: SUCCESS — 143/148 pass, 0 fail** (chromium). Run against staging after
the merge, before promotion.

## What shipped

Progressive per-account lockout: 5 free attempts, then 1/2/4/8/15 minutes, capped.
Chosen over a permanent lock because a permanent lock lets an attacker deny a real
user their own account by deliberately failing that user's login a few times.
Backoff self-heals.

The check sits ahead of the password compare and returns the identical generic
failure a wrong password returns, so a locked account stays indistinguishable from
a nonexistent one.

IP rate limiting was already in place and does not address this: password spraying
uses one attempt per account across many accounts, rotating source IPs.
